# 봇 통신 장애 자동 복구 검증 — 2026-09-28

## 변경 이유

2026-09-27 오전 통신 장애 중 1분 주기 봇 4개가 기존 10회 실패 조건으로 비활성화되었다. 네트워크 복구 후에도 DB enabled가 0이어서 재시작되지 않았고, 비활성 YouTube 채널이 DC 큐의 관리 채널 제외 대상에서도 빠졌다.

## 변경

- 통신 오류(DNS, 연결 실패, 타임아웃, 408/429/5xx)는 enabled를 유지하고 `recovering`으로 전환한다.
- 1→2→4→8→16→30분 대기 후 매분 복구 검사에서 재시도한다. 일반 cron/주간 집중 폴링도 같은 대기 시간을 적용한다.
- 성공 시 기존 주기로 복귀한다. 주간 폴링 창이 끝났어도 복구 검사는 계속한다.
- Redis에 재시도 시각/횟수를 저장하여 서버 재시작 시 이어간다. 수동 정지 및 오래된 실행 결과는 복구를 재활성화하지 않는다.
- 대기 진입/복구 완료 알림을 장애 구간별 각 1회 생성한다. 미발송 알림은 최신 상태로 대체한다. 실제 전달은 기존 DB 알림 대기열의 최소 1회 전달 정책이다.
- 키/권한/할당량 등 비일시적 오류는 기존 자동 정지 기준을 유지한다.
- YouTube JSON/HTML 오류 응답의 상태 코드를 보존한다. X 타임아웃만으로 세션 만료로 진단하지 않는다.
- 관리자 PC/모바일에 복구 대기·다음 재시도 KST 표시와 정지 동작을 적용했다.

## 검증

- 격리 Node 20 컨테이너에서 수집·스케줄러·운영 단위 테스트 **87개 통과**, DB 환경이 필요한 운영 통합 테스트 **4개 건너뜀**. pending-register DB 통합 테스트는 전용 DB 미설정으로 실행 대상에서 제외했다.
- 최종 스케줄러/API 회귀 **21개 통과**: 12회 연속 장애, 최대 대기 시간, 조기 실행 차단, 중복 실행 방지, 0건 복구, 재시작 유지, 주간 창 외 복구, 수동 정지와 늦은 성공/실패 결과, 응답 계약.
- 프론트 Vite 빌드 통과.
- 합성 API Playwright 검사: **320/390/1440px**에서 대기 상태·KST 재시도 표시, 정지 API 선택, 가로 넘침 없음, 브라우저 오류 없음. 캡처를 시각적으로 확인했다.
- 재현 스크립트: `frontend/test/mobile-admin-other/recovery.cjs`. 모든 API는 모의 응답이며 실제 봇을 정지시키지 않는다.

## 범위와 한계

- 운영 인터넷을 실제로 끊는 실험은 하지 않았다. 네트워크 오류와 시간 흐름은 격리 테스트에서 주입했다.
- DB/Redis와 백엔드가 함께 중단되면 메모리에만 있던 상태는 보존되지 않을 수 있다. 복구 후 기존 봇 시작 정책이 적용된다.
- 장시간 중단 중 게시된 콘텐츠의 완전한 재수집은 각 수집기의 조회 범위에 달려 있다.
- 기존 수집 큐/등록 일정을 삭제하거나 수정하지 않았다.

## 운영 반영 확인
