# 일정 검색·별칭 사전 개선 (2026-10-15)

## 반영 상태

- 운영 검색 엔진은 **Meilisearch 유지**. OpenSearch/Nori는 격리 비교 환경에만 남아 있다.
- 검색 별칭 관리 UI는 `/admin/schedule/dict`에 반영. 2026-10-16 운영 프론트 배포 완료([기록](../deployments/2026-10-16.md)).
- 백엔드는 개발/운영 공용 bind mount/watch 구성이다. 검색 API 개선은 웹 PC·모바일·앱 모두에 반영됐으며 APK 변경은 없다.
- 기존 일정 **2,423건 재색인 완료**. 일정 원본을 수정하거나 삭제하지 않았다. 운영 `/api/ready`의 database/redis/search 정상, 관리자 별칭 API 비인증 401 확인.

## 사전 관리

기존 **단어 사전**(Kiwi 형태소 분석의 명사 인식, 추천 검색어/초성 학습)을 보존하고 **검색 별칭** 탭을 추가했다. 기존 단어를 모두 동의어로 취급하지 않는다.

- 직접 관리: 대표 이름과 쉼표로 구분한 별칭을 추가·수정·삭제. 별칭 → 대표 이름의 단방향 확장. 제목의 원래 검색어 일치를 먼저 표시.
- 기본 연결: 프로미스나인 ← 프나/프미나/fromis_9/fromis, 건국대학교 ← 건대. 첫 저장 전 기본값으로 제공하고, 저장 후에는 관리자가 저장한 목록을 사용한다. 모두 삭제해도 기본값을 다시 넣지 않는다.
- 학교 자동 생성: 등록된 학교명에서 캠퍼스를 제외한 `○○대학교 → ○○대`. 현재 29개. 여러 캠퍼스는 같은 학교로 묶고, 각 연결을 끌 수 있다. 학교 일정 추가 시 다음 조회에 자동 반영된다. 직접 등록한 같은 별칭이 있으면 직접 관리 항목이 우선한다.
- 자동 연결 해제는 확장만 끄며, 엔진의 원래 접두어/오타 검색까지 금지하는 기능은 아니다.
- `지원` 같은 이름은 자동 연결하지 않는다. 기존 단어 사전에 등록돼 있다는 이유만으로 사람의 성을 보충하지 않는다.
- 대표 이름/별칭 간 중복과 순환 연결 가능성을 막고, 개수/길이/전체 저장 크기를 제한한다. 단어 경계에서 한 번만 확장하여 `건대입구`, `지원금` 등의 일부 문자열을 치환하지 않는다.
- 저장: 기존 `app_settings`의 `schedule_search_aliases` JSON. 새 테이블/스키마 변경 없음. SHA-256 revision 및 DB 조건부 갱신으로 동시 수정의 덮어쓰기 방지, 409 시 입력 유지·다시 불러오기 제공. 저장 성공은 `dict` 활동 로그에 기록한다.

## 검색 변경

- 기존 누락된 예능 방송사, 예능/행사/기타 설명, X 본문을 색인. 제목의 NFC 정규화와 공백·기호 없는 보조 필드를 추가했다.
- 일반 추가·수정, 큐, 봇, 전체 재색인이 같은 DB 조회/문서 생성 함수를 사용하도록 통일했다. 수동 예능/X/YouTube/콘서트 경로도 같은 동기화 함수를 사용한다.
- 검색 단계: 원문/공백·기호 정규화/등록 별칭 확장 → 결과가 없을 때 영문 자판 복구 → 단일 검색어에 제목의 실제 일치가 없으면 제목·출처 대상 오타 복구.
- 복합 검색은 모든 단어 일치를 요구한다. 결과가 없다고 조건 일부를 버리지 않는다. 별칭이 있는 짧은 원문에서 `건대 → 군대` 같은 오타 잡음도 제한한다.
- 제목 전체 또는 회차를 제외한 프로그램명이 정확히 일치하는 결과 우선. 그 안에서는 날짜/시간/ID 내림차순. 제목 내 원문 일치, 별칭 일치, 기타 관련도 순으로 이어진다. 모든 결과를 무조건 최신순으로 정렬하지 않는다.
- 숫자 오타 허용을 끄고, 검색어와 제목에 명시된 회차가 서로 다르면 제외한다. `계약결혼 2회`는 현재 1건이다.
- **조회 효율**: 검색 엔진에서는 순위/총개수 계산용 경량 후보(id/title/date/time/source/broadcaster)를 받고, DB PK 조회로 삭제된 ID를 제거한다. 상세 JOIN/포맷은 요청한 페이지에만 수행한다. 1,877건이 맞는 검색의 첫 페이지에서 상세 조회는 20건이었다.
- 정확한 총개수·별칭 병합·사용자 정렬을 보존하기 위해 경량 후보 최대 10,000건 조회는 유지한다. 엔진에서 무조건 20개만 받는 완전한 서버 페이지 처리나 대규모 확장 개선이 끝난 것은 아니다.

## 검증

- 검색/사전/API 권한/기존 검색 및 추천 입력 회귀 **20개 통과**.
- 격리 MariaDB에서 최초 동시 저장·갱신·대소문자 수정·이전 revision 차단·저장 유지 **1개 통과**.
- 큐 등록·실패 복구, YouTube/X 봇 및 수집 복구 **45개 통과**. 확장된 조회가 사용하는 테스트 테이블 필드를 보완했다. 수집 복구 테스트의 고정 10/1 날짜가 과거가 되어 실패하던 사례는 DB 기준 내일 날짜를 사용하는 fixture로 고쳤다. 운영 수집 로직은 변경하지 않았다.
- 실제 Meilisearch 1.34.0의 격리 `lab-improved`에서 기존 스냅샷 2,423건/62조건 비교. [검색별 결과](search-improvements-2026-10-15.json).
- 규칙 기반 nDCG@10 평균은 기존 0.862 → 약 0.884. 정답 없는 4조건은 모두 0건. 이는 사람의 검색 만족도/정확도 백분율이 아니다.
- `워크돌 박지원`, `이채영 MC`의 규칙 점수는 하락했다. 성이 빠진 이름·설명 일치의 의미를 규칙이 충분히 평가하지 못하며, 모든 단어 조건과 추가 메타데이터도 결과를 바꾼다. 멤버 관계를 자동 추론하는 기능은 구현하지 않았다. 모든 검색어의 품질 향상을 주장하지 않는다.
- 실제 공용 API 구현 직접 호출: 건대 1건(건국대), 호서대 1건(아산캠퍼스), JTBC 9건, 박지원 불참 8건, 계약결혼 2회 1건, 헬스키찬 41건, 서울대학교 POLARIS 0건. 이 검증은 검색어 학습 기록을 남기지 않았다.
- 방판소녀들 검색의 1위는 10/15 예정 일정(4048), 계약결혼의 1위는 가장 늦은 회차 유지.
- PC 1440px 브라우저: 탭 전환, 별칭 추가/수정/삭제 확인창, 409 입력 유지·재시도, 자동 연결 해제, 단어 사전 유지, JS 오류 없음. UI 검증은 모의 API로 운영 별칭을 변경하지 않았다.
- 프론트 빌드 성공. 기존 모바일/앱 검색 API 응답 형식 유지, 앱 자체 UI/실기기 검증은 이번 범위에 포함하지 않는다.

```bash
# 격리 검색 환경이 실행 중일 때, 실제 구현을 같은 스냅샷으로 비교

docker run --rm --network fromlog-search-lab_lab -e JWT_SECRET=isolated-search-test -v /docker/fromlog:/repo:ro -v /docker/fromlog/tools/search-lab/output:/repo/tools/search-lab/output -w /repo node:20-alpine node tools/search-lab/verify-improvement.mjs tools/search-lab/output/2026-10-15/snapshot.json tools/search-lab/output/2026-10-15/improved-results.json
```

- 색인 변경 전 문서/설정 백업: `tools/search-lab/output/before-improvement-2026-10-15/snapshot.json`(Git 제외).
- 저장된 별칭은 코드 배포와 독립적으로 DB에 남는다. 복구 시 사용자 입력을 삭제하지 않는다.
- 엔진/스키마 교체가 없어 코드와 검색 설정을 되돌린 뒤 DB에서 재색인할 수 있다. 오래된 스냅샷으로 일정 DB를 덮어쓰지 않는다.
