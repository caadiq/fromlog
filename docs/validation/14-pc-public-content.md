# 14. PC 공개 콘텐츠

- 상태: **부분 완료 — 공통 헤더·홈·멤버 우선 점검, 앨범 및 공통 미디어 뷰어 심화 검증은 후속**
- 검증일: 2026-09-26
- 변경 전 기준: `58280589`
- 환경: 개발 사이트, Chromium 자동화, 공개 GET 및 브라우저 내 모의 응답
- 범위: PC 공통 헤더/홈 푸터, 홈, 멤버 목록·5명 상세, 멤버 사진 목록의 기본 동작
- 제외: 앨범 목록/상세 본 검증, 관리자, 모바일 본 검증, 실기기, 다른 브라우저, 실제 Google/외부 SNS 로그인

남은 사용량을 고려하여 사용자 요청으로 2번보다 먼저 범위를 나누어 진행했다. 아래 결과를 14번 전체 또는 전 기기 검증 완료로 해석하지 않는다.

## 화면·스크롤 기준

홈과 멤버 페이지는 콘텐츠가 길면 OverlayScrollbars 내부 페이지가 세로로 스크롤된다. 문서 자체의 이중 스크롤과 PC 최소 폭 이상에서 가로 넘침은 없어야 한다. 헤더는 이 내부 스크롤에 고정된다. PC/모바일 경계는 CSS 폭 1100px이다.

실제 브라우저 자동화에서 사용한 검증 스크립트·캡처는 로컬 `/tmp/fromlog-public-audit/`에 있다. 장기 진행 기록의 정본은 이 문서다. `verify.cjs`는 배치·탐색·경계 조건, `motion.cjs`는 빠른 전환·가상 목록·사진 API 복구를 검사한다. 슬라이드 시계는 페이지 진입 전 설치하여 기존 타이머까지 포함했다.

## 발견 문제와 수정

| 문제 | 수정 |
| --- | --- |
| 존재하지 않는 멤버 사진 URL에서 무한 로딩 | 멤버 로딩/조회 실패/없는 멤버/사진 로딩을 구분 |
| 조회 실패를 빈 데이터처럼 표시하고 재시도 경로 없음 | 홈 각 섹션과 멤버 목록·상세·사진에 실패 안내·재시도 추가 |
| 홈에서 멤버 0명도 5명으로 표시, 앨범 0개는 대시 표시 | 로딩·오류와 실제 0을 구분 |
| 이미지 누락/404에서 깨진 이미지 표시 | 기존 비율·영역을 유지하는 `ContentImage` 폴백 적용 |
| 홈 멤버 카드가 모두 멤버 목록으로 이동 | 선택한 멤버의 상세로 연결, 전체보기는 목록 유지 |
| SNS 아이콘과 갤러리 사진 버튼에 접근성 이름 없음 | 링크/버튼 이름과 사진 필터 `aria-pressed` 추가 |
| PC 공통 전환·CSS 모션과 홈 자동 슬라이드가 동작 줄이기를 반영하지 않음 | 공개 Layout의 MotionConfig 및 범위 한정 CSS, 홈 슬라이드 정지 |
| 긴 이름에서 카드 폭이 늘어날 가능성 | 카드/프로필의 최소 폭·줄바꿈 처리, 모의 긴 이름으로 확인 |
| 푸터 CONTACT가 PC 최소 글자 크기보다 작음 | 11.5px → 12.5px |

`ContentImage`와 접근성 이름을 사용하는 공통 JustifiedGallery에도 변경이 있으므로 앨범 사진 갤러리를 후속 검증에 포함한다. 멤버 상세/사진 뷰어 입력은 목록과 동일하게 medium이 없으면 thumb를 사용한다.

## 검증 명령

- 로컬 Playwright로 개발 사이트의 위 브라우저 시나리오 실행.
- `docker exec fromlog-frontend npm run build`: 통과. 기존 큰 번들 크기·Browserslist 데이터 갱신 경고 유지.
- `git diff --check`: 통과.
- 운영 DB·일정·영상·봇 상태 변경이나 외부 API 한도 소비 없음. 오류는 브라우저 요청 가로채기로만 재현했다.
