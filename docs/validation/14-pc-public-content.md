### 기능·레이아웃·모션 검증

- 6개 경로의 503→재시도 성공, 빈 앨범/사진, 실제 404, 느린 곡 조회 중 잘못된 미등록 안내 없음.
- 앨범→곡→가사 펼침/접기→응원법. MV 없이 응원법만 있는 경우도 링크 표시.
- 소개창 Tab/Escape/Back, 사진 정보창 Escape/Back, 뷰어 닫힘 후 원래 버튼 초점, 브라우저 URL 유지.
- 사진 필터의 선택 상태, thumbnail 대체, 확대/해제, 마지막→첫 사진, 사진 점 클릭, 이미지/영상 실패→재시도/다른 항목 이동.
- 2초 단색 WebM의 실제 `canplay`와 닫힌 뒤 video 요소 제거. YouTube는 가짜 API로 오류 후 재시도·가사 시점 이동·키보드·destroy 확인.
- 600장 갤러리 끝 도달, 실제 마운트 사진 80개 미만, 빠른 12회 이동. 앨범 상세를 거쳐 재진입하면 기존 정책대로 필터 ALL/첫 위치로 초기화. 뷰어만 닫을 때는 선택 필터와 목록 유지.
- 긴 제목·크레딧·가사·18개 티저를 5경로×3크기(1100×450/1280×720/1920×1080), **15조합**에서 검사: 문서 이중 스크롤·가로 넘침·JS 예외 없음. 낮은 응원법 화면은 내용 접근에 필요한 내부/페이지 스크롤 허용.
- Chromium/Firefox/WebKit 각각 소개창·갤러리·정보창·닫기·이미지 점·동작 줄이기·CSS 1.5배 확대 확인. 각 엔진의 모든 페이지를 전부 재검증한 것은 아니다.
- 정상 모션 4회 개폐: 투명도 중간값 **111/127샘플**, 마지막 오버레이 제거·스크롤 잠금 해제. 강제 색상 모드 소개창도 확인.
- 공통 Lightbox 영향: PC 영상/일정 기존 extended 검사(9종 상세와 행사 포스터 뷰어 포함) 통과.

### 저장소 CORS 설정과 복구

공용 RustFS 중 **fromis-9 버킷 하나**의 CORS만 변경했다. 이전에는 CORS 설정 자체가 없었다.

- ID: `fromlog-public-media-read`.
- 허용 Origin: `https://fromlog.caadiq.co.kr`, `https://dev.fromlog.caadiq.co.kr`.
- 허용 메서드: **GET, HEAD**. Range 헤더 허용, 파일 크기/타입/이름/ETag 노출. 다른 버킷이나 객체 접근 정책은 수정하지 않았다.
- 개발 GET 206·운영 HEAD 200에서 해당 Origin 허용 헤더 확인. 다른 Origin에는 허용 헤더가 없고 PUT 사전 요청은 **403**.
- 실제 객체 쓰기·삭제 요청은 하지 않았다. 운영 데이터/봇 상태/외부 AI 변경 없음.
- 적용 전 백업: `/tmp/fromlog-album-audit/cors-before.json` 및 backend 컨테이너 `/tmp/fromlog-media-cors-before-20260927.json`(내용 `{ Bucket: "fromis-9", rules: [] }`).
- 재현/조회/적용/복구: `backend/scripts/configure-media-cors.mjs`. 기본 실행은 조회만 한다. `--apply <새 백업 경로>`는 기존 규칙을 보존하고 관리 규칙 하나만 반영한다. `--restore <백업 경로>`는 다른 규칙이 바뀌었으면 중단한다.
