# 9. 모바일 공개 영상·일정 검증

- 상태: 완료 (아래 범위 및 한계 기준)
- 날짜: 2026-09-27
- 대상: 개발 사이트 모바일 공개 `/video`, `/video/:category`, `/schedule`, 검색, `/schedule/:id`
- 방식: Chromium의 모바일 크기·터치 입력으로 실제 React 화면 + 합성 읽기 API 검사, 실제 개발 데이터 읽기 전용 확인
- 변경 범위: 프론트엔드. 공용 채널 선택·썸네일·달력·스크롤 초기화의 PC/관리자 영향도 확인. DB·봇·앱·운영 배포 변경 없음.

## 발견 및 수정

| 항목 | 확인한 문제 | 처리 |
| --- | --- | --- |
| 월말 다음 달 | 1월 31일에 `setMonth`를 먼저 호출하면 2월을 건너뛰고 3월로 이동 | 이동할 달의 1일을 먼저 생성. 펼친 달력과 헤더 이동 모두 적용 |
| PC ↔ 모바일 전환 | PC는 날짜 문자열, 모바일은 Date를 가정하여 회전/폭 변경 시 `getFullYear is not a function` | 공개 스토어의 선택 날짜를 YYYY-MM-DD로 맞추고 모바일 표시용 Date로 변환. 선택 날짜와 현재 월을 함께 저장 |
| 달력 애니메이션 | 공개 모바일 달력의 월 내용이 즉시 교체됨 | 관리자와 같은 방향별 20px 이동·각 0.08초 전환, 이전 달 종료 후 새 달 표시 |
| 날짜 띠·패널 | 날짜 가운데 맞추기 타이머가 빠른 이동 뒤에도 남음. 낮은 가로 화면에서 펼친 영역이 공간을 차지함 | 타이머 취소, 동작 줄이기에서는 즉시 이동. 달력/연월 패널 교체 순서 통일, 높이 제한과 내부 스크롤 |
| 상세 왕복 목록 위치 | 일정 및 검색 결과에서 상세를 보고 돌아오면 맨 위로 초기화 | 최근 30개 방문 상태에 스크롤과 가상 목록의 행 높이를 저장. 해당 목록만 전역 스크롤 초기화에서 제외. 새 검색은 맨 위에서 시작 |
| 영상 조회·추가 로딩 | 오류를 빈 목록과 구분하지 못하고 다음 페이지 실패 후 자동 재호출 가능 | 최초/추가 조회 오류와 재시도 표시, 실패 중 자동 호출 중단 |
| 채널 필터·썸네일 | 새로고침 시 필터 소실, 긴 채널명·이미지 전체 실패 처리 차이 | PC에서 검증한 선택기·썸네일을 공용화. URL 필터 복원, 화면 안 메뉴 높이 제한, 대체 이미지도 실패하면 영역 유지 |
| 일정 오류·상세 | 월 조회 실패가 빈 일정, 상세 500이 404로 표시. 상세 ID 변경 시 이전 내용 placeholder 사용 | 오류/빈 결과/404 분리, 재시도 제공, 이전 상세 placeholder 제거 |
| 긴 내용·날짜 미정 | 긴 URL 넘침 방지와 월만 확정된 일정 표시 보완 필요 | 상세 영역에서 긴 단어 줄바꿈, 날짜 미정/월 단위 표시 및 미정 D-day 생략 |
| 포스터 확대 | 닫기/정보/다운로드 아이콘에 접근성 이름 없음 | 이름과 44px 터치 영역, 이미지 뷰어 역할 추가 |
| 동작 줄이기 | 공개 모바일 레이아웃·상세에 공통 설정 없음 | 사용자 설정을 반영하는 MotionConfig 적용. 달력은 별도 즉시 전환 처리 |

## 실제 확인한 범위

### 화면·스크롤·애니메이션

- 320×568, 390×844, 844×390, 800×1100에서 긴 일정 35건, 고정 헤더/하단 메뉴, 가로 넘침과 목록 스크롤 측정.
- 위 일정 화면에서 전체 가로/세로 넘침 **0px**, 긴 목록은 `.mobile-content` 내부 스크롤. 낮은 가로 화면에서는 펼친 달력 자체도 스크롤하여 마지막 날짜를 선택할 수 있음.
- PC 분기 1099↔1100px 및 모바일↔1280px 전환 후 날짜 유지, 런타임 예외 없음.
- 4/5/6주 달력, 월 전진/후진, 1월 31일→2월, 연월 직접 선택, 빠른 연속 월 이동 및 패널 반복 개폐.
- 선택한 월말 날짜가 날짜 띠 안으로 이동함. 동작 줄이기에서 달력 잔여 이동 변환 없음.
- 실제 개발 데이터의 영상·검색·상세 및 가로 달력 캡처 확인.

### 영상

- 메인, 카테고리, 쇼츠, 긴 제목/채널명, 이미지 기본·대체 조회 실패.
- 채널 선택 URL, 새로고침 복원, 메뉴 키보드 End/Enter/Escape, 가로 화면에서 메뉴가 하단 내비게이션을 침범하지 않음.
- 첫 조회 실패/재시도와 실제 빈 목록, 24→48건 추가 조회, 추가 실패 시 자동 호출 정지 및 재시도.
- YouTube 일반 영상/쇼츠 주소, 새 탭 링크와 상세 iframe 주소 확인. 외부 앱 실행은 10번 범위.

### 일정·검색·상세

- 카테고리 선택, 상세 이동 후 복귀, 선택 날짜/필터 유지.
- 검색→상세→뒤로가기에서 검색어와 결과 복원, 다시 뒤로가기에서 빈 검색 화면.
- 일정 및 검색 목록 각각 850px 아래에서 상세 왕복 후 **850px로 복원**, 새 검색은 0px.
- 월별 조회 오류 및 다른 달을 펼쳤을 때 오류/재시도, 상세 500/404 구분.
- 유튜브 쇼츠, X, 행사, 예능, 기타, 팬사인회, 티켓팅, 콘서트, 기본 상세의 긴 제목·본문·URL: 320px에서 전체 및 상세 내부 가로 넘침 0px.
- 행사 포스터 확대→터치 스와이프로 두 번째 사진→브라우저 뒤로가기로 확대만 닫기, 다시 확대 후 닫기 버튼. 상세 URL 유지 및 스크롤 잠금 해제.
- 날짜 없음·월만 확정된 일정은 특정 일자/시간으로 표시하지 않음.
- 검색 입력 중 390×340으로 가시 영역을 줄인 조건에서 입력칸이 보임. 실제 OS 키보드 검증과는 구분함.

### 공용 변경 회귀

- PC 공개 영상/일정 회귀: 채널 선택, 오류 복구, 페이지 추가, 화면 크기별 스크롤, 검색/상세 왕복, 동작 줄이기.
- 모바일 관리자: 공용 CalendarPanel 열기, 날짜 선택, 다른 달 이동, 닫기. 관리자에는 공개 화면 전용 월 애니메이션을 중복 적용하지 않음.
- 프론트엔드 빌드와 `git diff --check`.

## 결과

- 합성 모바일 주요 검사·상세/터치 검사·스크롤 복원, 관리자 달력 및 PC 공개 회귀, 실제 개발 데이터 읽기 검사 통과. 확인한 흐름에서 런타임 예외 없음.
- 프론트엔드 빌드와 `git diff --check` 통과. 기존 번들 크기/브라우저 데이터 경고는 빌드 실패가 아니며 성능 점검은 13번 범위다.
- 개발 사이트 반영 및 검증 기록 완료. 다음 단계는 **10번 앱**이다.

## 한계·후속

- Chromium 모바일 크기/터치 에뮬레이션이다. 실제 Android/iOS 키보드, 주소창 접힘, Safari, 시스템 글자 확대 및 느린 실기기의 애니메이션 부드러움은 이번 검사만으로 확정하지 않는다.
- 앱 WebView·전체화면 재생·화면 회전·YouTube 앱 연결·실제 뒤로가기 버튼은 **10번 앱**에서 이어간다. 브라우저별 실기기 차이는 사용 환경에서 추가 확인한다.
- 공용 모바일 MotionConfig/Lightbox를 사용하는 홈·멤버·앨범의 전체 흐름은 **15번 모바일 공개 콘텐츠**에서 확인한다. 이번 포스터 검사로 해당 화면 전체를 완료 처리하지 않는다.
- 과거 단계의 접근 제한 영상 2건은 후속 항목을 유지한다. 모든 외부 영상 재생 성공을 보장하는 검사가 아니다.
- 개발 사이트 반영과 운영 배포는 별개다. 이번 단계에서 운영 배포·푸시는 하지 않는다.
