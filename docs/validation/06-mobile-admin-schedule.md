# 06. 모바일 관리자 일정

- 상태: 완료 (개발 웹 기준, 실기기 범위는 아래에 구분)
- 검증일: 2026-09-26
- 기준 버전: `7aa1696c` 이후 이 문서와 함께 커밋한 변경
- 환경: 개발 웹, Playwright Chromium. API 전체 응답 대역, 외부 호스트 차단.
- 범위: 로그인/홈/사이드바, 일정 목록·생성·수정·삭제, 수집 큐, 인스타 본문/포스터, 장소 입력, 뒤로가기·스크롤·키보드 대응·전환.
- 제외: 모바일 영상/봇/테마/로그/고정 링크는 11번, 공개 상세 화면 자체는 9번, 실기기/앱은 10번.

## 발견 문제·수정

| 문제 | 영향 | 수정 |
| --- | --- | --- |
| 일정 추가 중 브라우저 Back으로 저장 화면을 이탈 | 요청 완료 여부와 등록 결과를 놓칠 수 있음 | 생성 화면도 다이얼로그 Back 스택에 등록하고 저장 중 닫기 거부 |
| 개발 StrictMode의 effect 재실행이 새 Back 이력을 소비 | 팝업/화면이 예상과 다르게 닫힘 | 살아 있는 effect만 microtask에서 이력을 등록, 라우터 history 상태 보존 |
| 동작 줄이기 설정에서 추가 폼 닫기 후 빈 화면 | 애니메이션 종료 시 이동과 비동기 history.back이 충돌 | Back 이력 제거 완료를 기다린 뒤 생성 화면의 목적지로 이동 |
| 상세에서 돌아오면 날짜가 오늘로 초기화 | 선택 날짜·검색·읽던 위치를 잃음 | 같은 탭의 세션 저장소에 모바일 날짜·검색·스크롤 보존, 조건 변경 시에만 스크롤 초기화 |
| 장소 검색 실패가 표시되지 않고 늦은 응답이 재개방한 창에 나타남 | 실패/결과 없음 구분 불가, 이전 장소 선택 가능 | 오류/결과 없음 표시, AbortController와 요청 일치 검사, 닫기·Back 시 초기화, 아이콘 이름/터치 영역 보완 |
| 포스터·장소 팝업이 레이아웃 높이를 기준으로 표시 | 키보드가 나타나면 팝업 하단이 가려질 수 있음 | visualViewport 높이/상단 오프셋을 반영하고 내부 스크롤 유지 |

## 한계·후속 확인

- 실제 일정·큐를 등록하거나 삭제하지 않았습니다. 실제 API 통합은 2·4번 결과와 함께 판단해야 합니다.
- 실제 Instagram/YouTube/X/Kakao 원문, Google OAuth, Gemini 한도는 소비하거나 호출하지 않았습니다.
- 키보드는 `visualViewport.height=380` 모의 이벤트입니다. 실제 Samsung Internet/iOS Safari의 키보드·주소창·터치/제스처·관성 스크롤은 실기기 단계에서 확인합니다.
- 회전/큰 글자/전환 검사는 Chromium 기준입니다. 모든 기기에서 애니메이션 품질이나 프레임 손실이 없음을 보장하지 않습니다.
- 이번 범위에 남은 재현된 기능 오류는 없습니다. 사용 중 발견되는 기기별 문제는 해당 단계 기록에 추가합니다.
