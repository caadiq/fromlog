## 발견 문제·수정

1. **동시 X 수집 중복**: 조회 후 INSERT 사이 경쟁으로 같은 글이 중복 생성될 수 있었다. post_id별 DB advisory lock으로 직렬화했다. YouTube와 공유하는 잠금 슬롯은 DB 풀 여유를 남긴다.
2. **예정 일정 잘못 승격/정리**: 제목 부분 일치만으로 EP.1과 EP.10·다른 채널·쇼츠가 연결될 수 있었다. 채널/회차/유형을 검증하고, 승격 트랜잭션에서 행을 잠근 뒤 여전히 예정 상태인지 재확인한다. 번호를 판별할 수 없으면 예정 일정을 보존한다.
3. **일요일 마감 무시·잘못된 날짜**: `!deadlineDayOfWeek`가 0을 무효 처리했고 항상 어제 일정만 찾았다. 설정한 공개 요일로 마감 대상을 계산하고 그 날짜를 기준으로 다음 회차 날짜를 만든다.
4. **쇼츠 조회 일시 장애를 영구 오분류**: HEAD 실패 후 60초 이하를 쇼츠로 단정했다. 알 수 없는 상태를 유지해 다음 폴링에서 재시도한다. API 할당량/HTTP 오류도 없는 영상으로 숨기지 않는다.
5. **legacy 관련 영상 필터 재검사 불일치**: 연결된 본편 제목으로 통과해도 최종 저장에서 다시 거부했다. 확인된 연결 영상 정보를 최종 정책 검사까지 전달한다. 관련 영상 요청 장애는 제외 이력으로 저장하지 않는다.
6. **전체 조회 메타데이터**: durations 결과 객체를 boolean으로 사용하던 반환 형식 오류와 playlist 등록 시각 사용을 수정했다. 현재 수집 파이프라인은 유형을 재판별하므로 이 오류가 항상 쇼츠 오등록으로 이어진다는 뜻은 아니다. 길이·유형·영상 공개 시각을 올바르게 반환한다.
7. **공개 전 영상 링크**: `upcoming` 또는 길이 미확정 영상은 X에서 실제 영상 일정으로 등록하지 않고 다음 조회로 넘긴다. YouTube 상세 검사도 공개 예정/길이 미확정 데이터를 일정으로 확정하지 않는다.
8. **X 카드 링크 누락**: 본문뿐 아니라 카드 URL도 추출하며, 쿼리 순서·live/embed·HTML 엔티티를 처리한다.
9. **리트윗 오인·복원 누락**: 이전 목록 항목의 작성자를 사용하거나 짧은 공통 앞부분으로 다른 글을 합칠 수 있었다. 현재 글/RT 본문의 작성자를 사용하고, 완전한 본문은 전체 비교한다. 잘린 본문일 때만 접두부 비교를 허용한다.
10. **아카이브 추가 건수 과장·설정 재적용 누락**: 의도적으로 제외한 인터뷰/쇼츠도 추가 건수로 계산했다. 실제 INSERT/예정 승격 결과를 센다. `archive_shorts` 변경 시 처리·제외 캐시를 비워 새 정책을 평가한다.
11. **60분 cron·겹치는 실행·남은 타이머**: `*/60`을 시간 단위 cron으로 바꾸고 동일 봇 실행이 겹치지 않게 했다. 주간 폴링 만료 전 새 요청 시작을 막고 전체 정지/종료 때 타이머를 정리한다.
12. **Nitter 실패를 성공으로 처리**: 오류 HTML을 빈 타임라인으로 반환하거나 반복 커서를 끝없이 따라갈 수 있었다. 오류 페이지/반복 커서를 실패로 처리하고, 전체 수집이 반복 실패하면 부분 결과를 완료로 반환하지 않는다. 페이지 사이 같은 글은 중복 제거한다.

영상 공개 시각의 필드 의미는 [YouTube playlistItems 문서](https://developers.google.com/youtube/v3/docs/playlistItems#contentDetails.videoPublishedAt), 공개 예정 여부는 [videos 문서](https://developers.google.com/youtube/v3/docs/videos#snippet.liveBroadcastContent)를 참고했다.

## 재검증 근거

- 기존 YouTube 검사 **21개** 통과 후 재현 테스트 추가.
- 수정 전 소스 + 신규 실제 DB 시나리오: **11개 중 7개 실패** 재현. 동시 X 중복, 카드 링크, 공개 예정 영상, 경쟁 승격, 일요일 마감, 추가 건수, 리트윗 오인.
- 수정 후 실제 저장소 소스로 **68개 테스트 노드 모두 통과**(단위/회귀 39개, 통합 하위 시나리오 11개, 통합 그룹 1개, 기존 큐 등록 17개).
- 외부 fetch는 모의 응답으로 제한했고, 임시 DB 컨테이너는 외부 네트워크 없이 구동했다. 통합 테스트는 운영 DB 환경변수를 받지 않고 loopback의 별도 `bot_audit_*` DB를 만들고 제거한다.
- `/api/health` 200, 공개 봇 상태 정상 응답. CHOOM `youtube-14`의 `0 */1 * * *` 시작 및 동기화 완료 로그 확인.
- `git diff --check` 통과. 프론트/앱 변경 없음.

### 실행 방법

- 일반 회귀: `cd backend && JWT_SECRET=test npm run test:bots`
- DB 통합: 별도 MariaDB 11(root 빈 비밀번호, 외부 네트워크 차단)과 같은 network namespace에서 `BOT_AUDIT_DB=1 JWT_SECRET=test npm run test:bots:integration`.
- 통합 테스트를 운영 백엔드 컨테이너에서 DB 연결을 바꿔 실행하지 않는다. `backend/test/fixtures/bot-schema.sql`은 관련 테이블 정의만 포함하며 운영 데이터는 없다.
- 기존 큐 검사에는 별도 `fromlog_test_pending` DB와 `PENDING_TEST_HOST=127.0.0.1`이 필요하다.
