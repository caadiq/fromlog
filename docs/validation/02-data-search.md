## 확인한 오류와 수정

| 문제 | 수정 및 확인 |
| --- | --- |
| 검색 응답에 월 단위 날짜·앨범/콘서트 연결·원본 URL 누락 | 색인에서 찾은 ID를 달력과 같은 DB 조회/포맷으로 구성. 이미 삭제된 ID는 페이지 계산 전에 제외 |
| 월 단위 일정이 검색 화면에서 1일로 표시 | PC/모바일 공용 검색 행에 `9월 / 날짜 미정` 표시 |
| 검색 장애를 0건으로 반환 | 서버 오류 전파, PC 공개·모바일 공개·PC 관리자 검색에 재시도 안내 |
| 내부 검색이 1,000건에서 잘림, 동점 순서 불안정 | 색인 설정과 동일한 10,000건 후보 상한, 관련도→날짜→시간→ID 순 정렬 |
| 검색 하단이 계속 보이면 다음 페이지 로드 중단 | 로딩/오류 중에는 요청하지 않고, 하단이 보이거나 선택 카테고리가 아직 없으면 다음 페이지 계속 조회 |
| 느린 이전 자동완성 응답이 새 입력을 덮음 | effect 종료 후 도착한 응답 무시 |
| 일정 수정 후 공개 검색 캐시 잔존 | PC·모바일 검색 키 무효화 추가 |
| 카테고리 변경 후 목록·달력·색인에 이전 값 잔존 | 카테고리/월별 캐시 제거 및 해당 카테고리 일정 재색인 |
| 색인 작업 접수만으로 성공 판단, 빈 DB/일시 DB 실패 시 색인 삭제 재생성 | 실제 task 성공 확인. 전체 동기화 실패는 오류로 전달. 재시도 시 기존 색인 보존 |
| PC 관리자 영상 날짜가 UTC→KST 재변환되어 하루 밀림 | 공개/관리자 API 모두 KST 벽시계 문자열로 통일, PC 날짜를 문자열에서 표시. 멤버 JSON도 배열로 반환 |
| 같은 시각 영상의 페이지 순서 불안정 | 영상 정렬에 ID 내림차순 추가 |
| 영상/일정에서 형식을 수정하면 상대 데이터원에 미반영 | 하나의 트랜잭션으로 양쪽 변경, 서버 월별 캐시 및 웹 영상·일정 캐시 무효화 |
| 수동 YouTube 일정 저장 중 일부 실패 시 고립된 일정 생성 가능 | 일정·YouTube 상세·영상 보관함 적재를 하나의 트랜잭션으로 처리 |
| Node 프로세스 시간대에 따라 월말·생일·데뷔일 하루 이동 가능 | DB wall-clock 해석 timezone 고정, 달력 날짜 생성에 UTC 연산 적용 |

색인이 일시 중단되어도 완료된 일정 DB 저장 자체는 취소하지 않는 기존 정책은 유지한다. 단건 동기화 실패는 서버 로그/반환값으로 확인하며, 영구 재시도 큐·봇 재시작 복구는 3·4·12번 범위다.
