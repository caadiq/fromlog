### 기록 규칙

- 진행 시작 시 표의 상태를 변경하고 해당 파트의 결과 문서를 연결한다.
- 결과 문서는 `docs/validation/NN-주제.md` 형식으로 만든다. 실제 검증을 시작할 때 생성한다.
- 세부 체크박스는 실제 확인 후 표시한다. 기존 구현 완료나 과거 테스트 통과만으로 체크하지 않는다.
- 같은 검사를 반복하지 않도록 다른 파트에서 확인한 근거를 연결한다. 변경 영향이 있으면 재검증한다.
- 문제가 많으면 해당 파트만 작은 하위 작업으로 나누며 원래 번호는 유지한다.
- 완료 시 미해결 문제·미검증 범위·실기기 확인 필요 항목을 구분한다. 필수 확인이 남으면 완료로 표시하지 않는다.
- 기능 검증 완료와 운영 배포 완료는 별도로 기록한다. 개발 사이트에서 검증하고 운영 배포는 기존 승인 원칙을 따른다.

## 공통 검증 기준

### 화면이 있는 모든 파트

- [ ] 대상 페이지·다이얼로그·주요 조작을 먼저 목록화하고 누락 여부 확인
- [ ] 정상 동작, 뒤로가기·앞으로가기·새로고침·직접 URL 진입
- [ ] 검색·필터·페이지·선택 날짜·스크롤 위치 등 필요한 상태 복원
- [ ] 긴 제목·빈 목록·많은 데이터·값 0·이미지 없음/실패·느린 로딩·오류 상태
- [ ] 저장 중 중복 클릭·입력 중 이탈·실패 후 재시도
- [ ] 키보드 조작·포커스·아이콘 버튼 이름·글자 대비·터치 영역

이 체크리스트는 **각 파트의 결과 문서에 복사하여 따로 체크**한다. 한 파트의 확인을 전체 화면의 확인으로 취급하지 않는다.

### UI·스크롤·화면 크기

- PC: 일반 화면, 낮은 높이, 태블릿 가로, PC 분기 경계인 1100px 전후를 확인한다.
- 모바일: 좁은/넓은 화면, 태블릿 세로, 회전과 PC·모바일 전환을 확인한다.
- 브라우저 확대와 글자 크기 변화도 주요 화면에서 확인한다.
- 가로·세로 넘침은 `scrollWidth/clientWidth`, `scrollHeight/clientHeight`와 요소 위치를 측정하고 화면 캡처로 확인한다.
- 페이지 스크롤과 목록 내부 스크롤의 **의도된 동작을 먼저 기록**한다. 모든 스크롤을 오류로 분류하지 않는다.
- 고정 헤더·푸터·플로팅 버튼·팝오버의 겹침, 잘림, 불필요한 이중 스크롤을 확인한다.
- 데이터·이미지·폰트가 뒤늦게 로드될 때 높이 계산과 화면 밀림을 확인한다.
- 모바일 키보드·브라우저 주소창 접힘·앱 웹뷰는 자동 검사와 실제 기기 확인을 구분한다.

### 애니메이션 — 모든 화면 파트에 포함

- 등장·퇴장 방향, 속도, easing과 사이트 내 일관성
- 패널과 반투명 배경의 전환 시점, 깜빡임, 퇴장 중 멈칫함
- 빠른 반복 개폐, 연속 클릭, 전환 도중 뒤로가기·페이지 이동
- 닫힌 요소가 보이거나 클릭·터치 영역에 남는 문제
- 목록 추가·삭제·정렬·필터 변경 시 위치 이동과 높이 변화
- 달력·탭·페이지 전환, 날짜/시간 선택기, 사이드바·플로팅 메뉴
- 애니메이션 중 스크롤 발생, 포커스 손실, 스크롤 잠금 해제 누락
- 느린 기기에서 끊김과 `prefers-reduced-motion` 환경의 사용 가능 여부

### 데이터 변경·운영 검사

- 조회만으로 가능한 검증을 우선하고, 등록·삭제·실패 재현은 테스트 데이터·격리 환경을 사용한다.
- 실제 일정·영상·봇 상태를 변경해야 할 경우 대상과 복구 방법을 먼저 명확히 한다.
- 푸시 발송, 외부 API 호출, API 한도 소비 등 실제 부작용을 기록한다.
- 비밀값·인증 정보·개인정보는 결과 문서와 캡처에 남기지 않는다.
- 자동화 검사로 확인한 범위와 실제 기기에서 확인한 범위를 구분한다. 전 기기 무결함을 보장한다고 표현하지 않는다.
